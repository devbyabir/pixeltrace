Project report

PixelTrace: detecting AI-generated images, and measuring it honestly. Abir Ahmmed (devbyabir), 2026.

1. Summary

The first version of this project, a set of student notebooks, reported 93–99.6 % accuracy at telling AI-generated images from real photographs. An audit showed those numbers were not trustworthy: the test images leaked into training, almost every image existed twice, and the labels could be predicted from file metadata alone. PixelTrace rebuilds the experiment so that the reported number means what it says. The deployed model, , reaches test accuracy (95 % CI ) and a test ROC-AUC of on images it has never seen.

2. Problem

Given one image, output a score for how likely it is to be AI-generated. Two errors matter: flagging a real photo as fake, and passing a generated image as real. A score is not proof: it is only as good as the data the model has seen.

3. Data and audit

  • files received from a senior colleague, in two folders (AI-generated, real). Original source, generators and licence are unknown, so no images are published.
  • files were exact copies (1,998 images stored twice, 2 once), leaving unique images.
  • The classes differed in file properties: AI images were mostly square, often PNG and often carried EXIF; real photos mostly non-square JPEGs. A classifier using only those properties, never the pixels, scored on the test split. That is a shortcut risk, not proof of what the old models learned.
  • The legacy notebooks also split the data with a dataset that reshuffled every epoch (test images leaked into training) and picked checkpoints on the test set.

4. Method

  1. De-duplicate, then split once: exact (SHA-256) and near-duplicate (perceptual hash) removal; stratified / / split, frozen in a manifest of file hashes so anyone with the data can verify the identical split.
  2. Remove the known shortcuts: every image centre-cropped to a square, re-encoded as JPEG q95, metadata stripped. Afterwards the remaining file-size cue scores (near chance).
  3. Models: a CNN trained from scratch, and ImageNet-pretrained ResNet-50 and EfficientNet-B0 fine-tuned with AdamW, a cosine schedule and mild geometric augmentation. Trained on a Tesla T4 GPU.
  4. Selection on validation only: the best checkpoint of each model and the deployed model were chosen by validation ROC-AUC. The test split was evaluated once at the end.
  5. Evaluation: accuracy, macro-F1, AI precision/recall and ROC-AUC from probabilities, with 1,000-sample bootstrap 95 % confidence intervals; robustness to JPEG compression, down-scaling and blur; Grad-CAM inspection (kept private because it shows dataset images).
  6. Verification: an automated step checks that every checkpoint reloads to the same predictions, that the original image files give the same scores as the cleaned copies, that every metric can be recomputed from the saved per-image predictions, and that the browser (ONNX) model matches PyTorch.

7. Limitations

  • Small, single-source dataset from unknown generators: the results do not show the model works on other generators, edited images or real-world photo pipelines.
  • Real photos were downscaled from much higher resolutions than the AI images; resampling leaves statistical traces a model may still exploit. Cleaning removed the format, shape and metadata cues, not this one.
  • 300 test images give confidence intervals several percentage points wide.
  • The demo's score is a model output, not evidence that an image is authentic or fake.

8. What I learned

A high accuracy number is only meaningful together with how it was measured. Auditing my own earlier work for leakage, duplicates and shortcuts mattered more than adding another model architecture, and making every number re-computable from saved predictions made the final results defensible.
