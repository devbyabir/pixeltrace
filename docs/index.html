What the audit found

The original notebooks reported 93–99.6 % test accuracy. Re-reading them and the data showed four problems:

Leaky split

The train/test split was taken from a dataset that reshuffles every epoch, so test images could be seen during training.

Duplicates

… of the … files were exact copies: 1,998 images appeared twice under different names.

Test set used for selection

The same images were used to pick the checkpoint and to report the final score.

Metadata shortcut risk

A model that never sees a pixel, only aspect ratio, PNG/JPEG, EXIF and file size, scores … on the test split.

The metadata result shows the labels were predictable from non-content cues, a risk for any model trained on the raw files. It does not prove what the legacy CNNs actually learned. After cleaning (square crop, JPEG re-encode, metadata stripped), the remaining file-size cue scores …; other shortcuts may remain (see limitations).

Limitations

  • Small, single-source dataset of 2,000 images from unknown generators. Results say nothing about other generators or real-world photos.
  • Residual confound: real photos were downscaled from much higher resolutions than the AI images. Resampling statistics can still separate the classes, and cleaning does not remove that.
  • Small test set (… images): confidence intervals span several percentage points.
  • Unknown dataset licence: no dataset images or image-derived figures are published here.
  • Browser vs Python: the browser reproduces the Python preprocessing exactly except for the JPEG re-encode step, which uses the browser's codec; see the parity check.

Reproduce

Code, configs, the split manifest (hashes only) and the Colab notebook are in the repository. The full pipeline (data audit → training → robustness → Grad-CAM → model selection → ONNX export → verification) runs with one command and stops on the first error.
